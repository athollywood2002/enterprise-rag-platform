# Reliability and grounding changes

The unchanged 30-question baseline is preserved in PR #28. These changes do not rescore it.

* T15: HTTP compatibility is retained (`answer` remains empty and generation evidence remains intact). An additive `generation_notice` explains an empty output and appears in the browser next to the excerpts. No automatic inference retry or global cap increase. Thinking is not established as the cause.
* `OLLAMA_THINK=default|on|off` defaults to existing model behavior. Explicit on/off checks `/api/show` for the exact requested boolean in `thinking.values` before inference and sends a boolean `think` field. Invalid values fail configuration. The installer pins Ollama 0.40.15; its native thinking API is documented by [Ollama](https://github.com/ollama/ollama/blob/v0.40.15/docs/capabilities/thinking.mdx). Keep `default` for servers/models without that capability. `OLLAMA_NUM_PREDICT` remains separately validated; the installer keeps 1536. No thinking response field is stored or displayed; tagged reasoning in older/custom content is removed too. Real-model latency and quality for each setting require a separately authorized measurement.
* T21: managed queries fuse dense candidates (at least 20) with BM25 passage candidates over committed, selected revisions using reciprocal-rank fusion. Compatible parser collections are pooled before calculating global dense ranks, BM25 statistics/ranks and reciprocal-rank fusion. A bounded scan reads at most 5000 chunks per collection; response metadata discloses each collection and aggregate truncation/limits. Identical candidates produce the same ranking and fusion scores whether stored together or split across collections, provided the candidate/scan limits do not exclude different passages. Ties use stable revision/chunk point IDs. No new search service or embedding/reindex is needed for this retrieval change. Legacy `/ask` remains dense-only. This is suitable for the small demo, not a large-corpus scalability claim. A regression distinguishes the answer-bearing action passage from the same document's timeline and retrieves lexical candidates absent from dense results.
* T06/T18/T20/T25: managed generation instructions require exact-excerpt support, material conditions, effective-date precedence, and abstention when a replacement rule is absent. They prohibit extrapolating contract terms from unrelated policies. These are grounding safeguards, not semantic verification: valid citation numbers still do not prove support, and real-model improvements remain unmeasured. The UI calls the list retrieved excerpts rather than asserting every entry is cited.
* Installer: the owned API exemption requires matching loopback address and published port, running state and Compose ownership. A real listener on a requested new port fails the bind/listen probe. TIME_WAIT handling is retained.
* Watchdog test: startup no longer competes with the tiny test deadline. The real deadline timer is armed after the response enters its event handler with a live registered child; a bounded process wait proves watchdog termination despite the held event lock. SIGKILL and deadline assertions remain.

Offline checks use generated fixtures and mock model transports; no inference or retained installation is touched. Existing API keys, volumes, replacement and cancellation mechanisms are unchanged.
